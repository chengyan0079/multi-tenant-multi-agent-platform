# 接口与权限梳理

> 本文档逐模块梳理「前端页面接口对接现状与测试清单」里的 3.x 功能点，对齐后端接口、当前鉴权、前端接入状态，
> 以及本次「按权限收敛 + 前端二次确认」目标下的差距。权限模型以《登录与权限校验说明》为准。
> 代码基线：后端 `backend/api/v1`，前端 `dashboard/src`。

## 0. 身份与权限速览

三级身份（按 `agent_user_tenant` + `tenant.is_primary` + 角色名判定，不写死 id）：

| 身份 | 判定 | token 租户 | 能力边界 |
|---|---|---|---|
| 平台超管 | `agent_user.is_super_admin=true` | 无（恒 `None`） | 基建域（`/admin/**`）；不进业务链路 |
| 租户管理员 | 角色名 `tenant_admin` | 有 | 本租户用户/角色（`/tenant/**`），不可跨租户 |
| 普通用户 | `student` / `teacher` 等（不预置，由超管创建） | 有 | 业务使用 |

关键 scope（来自《登录与权限校验说明》§6.6）：

| scope | admin | tenant_admin | student/teacher |
|---|---|---|---|
| `agent:read` / `agent:write` | ✅ | ❌ | ❌ |
| `model:read` / `create` / `update` / `delete` | ✅ | ❌ | ❌ |
| `config:read` / `config:update` | ✅ | ❌ | ❌ |
| `tenant:read` / `tenant:write` | ✅ | ❌ | ❌ |
| `rbac:read` / `rbac:write` | ✅ | ✅ | ❌ |
| `audit:read` | ✅ | ✅ | ❌ |
| `qa:read` | ✅ | ✅ | ✅ |
| 监控看板（`/dashboard`） | ✅ | ✅ | ❌ |

后端鉴权装配（`backend/api/router.py`）：

- `/api/v1/admin/**` 整组 `require_super_admin()`（超管独占，含 tenants/users/roles/rbac/audit/config/agents/plugins/models/menu）
- `/api/v1/tenant/**` 整组 `require_tenant()`（超管 403）；`tenant/users`、`tenant/roles`、`tenant/audit` 再叠加 `require_tenant_admin()`
- `/api/v1/dashboard` 挂 `require_admin_or_tenant_admin()`（超管全局 / 租户管理员本租户）
- `/api/v1/health`、`/metrics` 免鉴权

## 2. 前端通用改动

### 2.1 菜单按权限渲染（核心缺口）

`dashboard/src/layouts/MainLayout.tsx` 的 `menuItems` 是**硬编码数组**，所有角色都能看到全部入口，
与后端 scope 控制不一致（普通用户也能看到「智能体管理/模型注册表/配置中心/审计」等）。

登录响应已携带 `menus`（后端按 `menu.scope` 过滤，超管下发基建菜单、租户管理员下发改/审计、普通用户只业务菜单）。
**改动**：`MainLayout` 改为读取 `localStorage.ap_session` 里的 `menus` 渲染侧边栏，path→组件映射仍由前端白名单维护。
这样各模块的前端可见性自动符合目标权限，无需逐页加 `if` 判断。

### 2.2 二次确认（缺失项）

现状只有两处 `Popconfirm`：模型删除、配置执行 Nacos。以下写操作**缺二次确认**，需补齐：

- 角色管理：删除角色（`DELETE /admin/roles/{id}`）
- 菜单管理：删除菜单节点（`DELETE /admin/menus/{id}`）
- 租户管理：改名、启停、指定/更换管理员（`PUT /admin/tenants/{id}`、`.../manager`）
- 用户管理：改角色（`PUT /admin/rbac/users/{user_id}/role`）、解绑（租户侧 `DELETE /tenant/users/{user_id}`）
- 模型注册表：编辑、启用开关、删除（删除已有，编辑/启用缺）
- 配置中心：复核、回滚、删除申请（`review` / `rollback` / 删申请单）

统一用 `Popconfirm`（行内操作）或 `Modal.confirm`（表单提交类）包裹，确认文案说明后果。

## 4. 实施结论与现状

三项取舍已确认并按此实施：

1. **3.9 角色对租户管理员：仅查看**。角色目录读取（`GET /admin/roles` 及其权限点）对超管 + 租户管理员开放；
   覆盖写权限点（`PUT /admin/roles/{id}/permissions`）仅超管。实现：rbac.py 读接口挂 `require_admin_or_tenant_admin()`，
   写接口挂 `require_super_admin()`；该模块不挂整组 `require_super_admin()`（见 api/router.py 注释）。
2. **前端菜单：后端 `menus` 驱动**。`MainLayout` 改为读取登录响应 `session.menus` 渲染侧边栏（按 scope 已过滤，自动贴合权限），
   不再硬编码。后端 `MenuDao.build` 统一按 scope 过滤（原超管白名单会丢 `/rbac` 子项）；新增 `menu:manage` scope（仅超管）
   用于菜单管理页，种子（`schema.sql` + `gen_schema.py`）与 `DEFAULT_ROLES` 已同步。
3. **二次确认：所有写操作**。删除、改名、启停、换管理员、改角色、解绑、覆盖权限点、启用切换、通过复核等即时操作均加 `Popconfirm`/`Modal.confirm`；
   表单类提交（新增/编辑/发起申请/回滚）沿用 Modal 提交即确认。

### 后端改动

- `backend/api/router.py`：rbac 路由不挂整组超管，单独挂载由各端点声明鉴权。
- `backend/api/v1/admin/rbac.py`：角色读放开超管 + 租户管理员；写接口（权限点覆盖/新建/删除/改用户角色）仅超管。
- `backend/security/rbac.py`：新增 `Scope.MENU_MANAGE`，`DEFAULT_ROLES` 超管权限点加入。
- `backend/data/dao/auth/menu_dao.py`：`build` 统一按 scope 过滤。
- `backend/api/v1/admin/menu.py`：接口 scope 改为 `menu:manage`。
- `scripts/schema.sql` + `scripts/gen_schema.py`：种子权限点加入 `menu:manage`。

### 前端改动

- `dashboard/src/layouts/MainLayout.tsx`：菜单改后端 `menus` 驱动 + icon 映射。
- `dashboard/src/pages/rbac/RoleList.tsx`：删除角色、覆盖保存权限点加确认。
- `dashboard/src/pages/rbac/MenuList.tsx`：删除菜单加确认。
- `dashboard/src/pages/rbac/TenantList.tsx`：保存改名/启停、更换管理员加确认。
- `dashboard/src/pages/rbac/UserList.tsx`：修改用户角色加确认。
- `dashboard/src/pages/ModelList.tsx`：启用切换加确认（删除已有）。
- `dashboard/src/pages/ConfigCenter.tsx`：通过复核加确认（执行已有）。
