# 数据库设计文档

> 现行实现基线（2026-11-16）。DDL 由 `scripts/gen_schema.py` 从 `backend/data/postgres` 的模型类生成到 `scripts/schema.sql`。
> 种子数据见 `scripts/seed_data.sql`；增量变更见 `scripts/migrations/`。

---

## 1. 约定

| 项 | 约定 |
|---|---|
| schema | 由 `POSTGRES_SEARCH_PATH` 配置（默认 `unified_schemas`）；涉及同名历史表时**显式带 schema 查询**（如 `graph_states` 的 checkpoints） |
| 访问方式 | 运行期**不用 ORM**：DAO 全为 `text()` 手写 SQL；模型类仅用于生成 DDL |
| 主键 | UUID（`gen_random_uuid()`），字符串形式返回 |
| 审计列 | `create_at / update_at / create_user_id / update_user_id / create_tenant_id / update_tenant_id`（`AuditMixin`）；`update_at` 由触发器维护 |
| 软删除 | 会话/业务行用 `status`（`active/archived/deleted`）表达，物理删除仅限明确入口 |
| 隔离 | 所有业务表带 `tenant_id`，查询强制按租户过滤；写库失败**不降级**，直接抛出由接口返回 `code/msg` |

## 3. 核心表字段

### 3.1 `agent_thread`（会话）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 会话 thread_id（前端「会话管理」展示/过滤用） |
| `session_key` | varchar | 会话键（`/unified/chat` 的 `session_id`） |
| `tenant_id` / `user_id` | bigint | 隔离维度 |
| `title` | varchar | 首轮自动命名（仅当为空时写一次） |
| `status` | varchar | `active/archived/deleted` |

> 删除会话**只删此行**；turn / 评测 / checkpoint 保留，仍可在「咨询结果」查看与测评。

### 3.2 `agent_unified_turn`（轮次）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 轮次 ID（=「咨询结果」的 `id`） |
| `thread_id` | UUID | 所属会话 |
| `trace_id` | varchar | 链路追踪 |
| `turn_index` | int | 轮次序号；**唯一索引 `(thread_id, turn_index)`**，由 `max+1` 计算 |
| `agent_type` | varchar | `qa` / `db_review` / `db_release` |
| `event_type` | varchar | `chat` / `task_result` 等 |
| `user_content` / `assistant_content` | text | 问答正文 |
| `payload` | jsonb | `answer_mode` / `confidence` / `sources` / `retrieved_contexts` / `execution_mode` |
| `routing` | jsonb | 路由决策快照 |
| `status` / `error_code` / `error_msg` | — | 执行状态与错误 |
| `latency_ms` | int | 本轮耗时 |
| `token_usage` | jsonb | `{prompt, completion, total, estimated?}` |

索引：`thread_id`、`(tenant_id, user_id, thread_id, turn_index)`、`(tenant_id, agent_type, create_at)`、`trace_id`、`(tenant_id, create_at)`、唯一 `(thread_id, turn_index)`。

### 3.3 `agent_qa_ragas_evals`（评测）

| 字段 | 说明 |
|---|---|
| `turn_id` | 评测对象（`agent_unified_turn.id`），索引 |
| `reference_answer` | 人工标准答案（**必填**，否则接口 400 / handler 直接 failed） |
| `retrieved_contexts` | 评测时的上下文快照（JSONB） |
| `faithfulness / answer_relevancy / context_precision / context_recall / answer_correctness` | 5 项指标（Numeric(6,4)，可空） |
| `metrics` | 原始指标明细（JSONB） |
| `status` | `pending / success / failed` |
| `eval_at` | 评测时间 |

### 3.4 其他关键表

- `agent_long_term_memory`：`tenant_id / user_id / agent_id / block / content`，`embedding_id` 为语义召回预留（当前空）；
- `agent_knowledge_pending_queue`：`question / user_id / confidence / status`，`resolved_user_id`、`resolved_at` **可空**（待处理时无处理人）；
- `agent_file`：MinIO 对象键、`parse_status`（`pending/parsing/parsed/failed`）、`file_hash`；
- `agent_change_request`：`sql_text / db_type / target_database / risk_level / status`；
- `agent_outbox`：`id（=消息 key）/ topic / message_kind / payload / status / retry_count`。

## 4. 检查点表（LangGraph）

| 表 | 说明 |
|---|---|
| `checkpoints` | 每个 superstep 一行（`thread_id / checkpoint_ns / checkpoint_id / parent_checkpoint_id / checkpoint / metadata`） |
| `checkpoint_blobs` | 序列化后的通道值 |
| `checkpoint_writes` | 待写通道 |

- 分区：父图 `thread_id = 会话U`；子图 `{U}:{agent_type}:{turn_id}`；
- `metadata` 为 JSONB（`step / source / tenant_id / user_id / trace_id / agent_type`），读取时需 `json.loads`；
- 查询必须带 schema（`graph_states.py` 已按配置拼 `{schema}.checkpoints`），避免同名历史表混淆。

---

## 5. 索引与查询约定

- 列表类查询必须带 `tenant_id`，并尽量命中 `(tenant_id, create_at desc)`；
- UUID 模糊筛选用 `CAST(col AS text) LIKE '%...%'`（管理页可接受，不做高频）；
- JSONB 取值统一 `payload->>'field'`，聚合前 `CAST` 为 `bigint/numeric` 避免 Decimal 序列化问题；
- 异步任务表（`agent_outbox` / `agent_dead_letter`）按 `status + create_at` 扫描。

---

## 6. 数据生命周期

| 数据 | 写入 | 删除 |
|---|---|---|
| 会话 | 首次提问 `get_or_create` | 删会话只删 `agent_thread` |
| 轮次 | 每轮结束 `append_turn`（失败即报错） | 随会话删除**不删**（保留历史与报告） |
| 评测 | 人工标准答案后插 `pending` → MQ 回填 | 手动清理（可选入口） |
| 检查点 | 图每步写入 | 不随会话删除（避免误伤 HITL） |
| 短期记忆 | 每轮 Redis push（TTL 1 天） | 过期自动 |
| 长期记忆 | 摘要/审批关键节点 | 手动清理 |
