# 登录与权限校验说明

> 现行实现基线（2026-11-16）。覆盖「登录认证 → 请求身份解析 → 授权（RBAC）→ 菜单下发」四层。
> 代码：`backend/middleware/auth.py`、`backend/security/rbac.py`、`backend/api/v1/auth/**`、`dashboard/src/services/{auth,http}.ts`。

---

## 1. 四层链路

```
① 登录    POST /api/v1/auth/login  → 校验账号密码 → 签发 JWT（含 user_id / tenant_id / jti）
② 身份    Authorization: Bearer <JWT> → 验签 + Redis 会话校验 → CurrentUser
③ 授权    require_scope("资源:动作") → 查角色权限点 → 放行/403
④ 菜单    GET /api/v1/auth/menus → 按 role 的 scope 过滤 agent_menu
```

**身份只来自 JWT**：不读任何身份请求头、不保留开发默认身份；缺失/失效一律 401。

---

## 2. 登录与 JWT

| 项 | 说明 |
|---|---|
| 算法 | `JWT_ALGORITHM`（默认 HS256），`JWT_SECRET` 必填 |
| 有效期 | `JWT_EXPIRE_MINUTES`（默认 1440） |
| 会话控制 | 登录写 Redis `jti`（TTL `SESSION_TTL_SECONDS`，默认 900s），每次请求滑动续期；超过无请求即失效 |
| 登出 | 删除 Redis `jti` → 旧 token 立即失效 |
| 日志 | 成功/失败均写 `agent_login_log`（旁路，写失败不影响登录） |

`CurrentUser` 关键字段：`user_id`、`tenant_id`、`home_tenant_id`、`role_name`、`is_super_admin`、`is_tenant_admin`。

---

## 3. 权限点规范

格式：`资源:动作`（`Business` × `Action`），共 **83 个**，定义在 `backend/security/rbac.py::Scope`，`VALID_SCOPES` 为白名单。

### 3.1 统一咨询（`unified:*`，12 个）

| 权限点 | 用途 |
|---|---|
| `unified:ask` | 统一咨询提问（qa / db_review / db_release 共用） |
| `unified:menu` | 「统一咨询」菜单可见 |
| `unified_session:page` / `view` / `delete` | 会话列表 / 详情回放 / 删除 |
| `unified_turn:page` / `view` / `review` | 咨询结果列表 / 详情与测评报告 / 发起质量测评 |
| `unified_file:page` / `view` / `upload` / `download` | 知识库文件列表 / 详情 / 上传 / 下载 |

> 旧 `qa:ask`、`qa_result:*`、`qa_session:*`、`qa_file:*` **已全部删除**，迁移见 §8。

## 4. 授权实现

```python
# 接口声明
_: object = Depends(require_scope(Scope.UNIFIED_TURN_PAGE))
```

- `require_scope` 从 `CurrentUser.scopes` 判断；缺失 → 403（`{code: FORBIDDEN, msg}`）；
- **超管**（`is_super_admin`）访问 `admin/**`；**租户用户**访问 `tenant/**`（超管无租户上下文，调租户接口 403）；
- 业务域内再细分：会话/结果/文件各自独立权限点，便于"只给查看不给删除"。

**运行期二次校验**（图内 `_authorize`）：入口 scope + 租户开通（`agent.enabled`）+ `spec.scope`（三个 Agent 均为 `unified:ask`）。

---

## 5. 菜单下发

- 菜单存 `agent_menu`，每项带 `scope`；登录后 `GET /auth/menus` 按用户 scope 过滤；
- 路由守卫与菜单 scope 对应（见 `dashboard/src/App.tsx`）：

| 页面 | 路由 | scope |
|---|---|---|
| 业务咨询（聊天框） | `/consultation/chat` | `unified:ask` |
| 会话管理 | `/consultation/sessions` | `unified_session:page` |
| 会话详情 | `/consultation/sessions/:threadId` | `unified_session:view` |
| 图状态列表 | `/consultation/graph-states` | `unified_session:page` |
| 咨询结果 | `/consultation/results` | `unified_turn:page` |

前端用 `hasScope('unified_turn:page')` 做按钮级控制（如「开始测评」需 `unified_turn:review`）。

---

## 6. 数据隔离

| 层 | 机制 |
|---|---|
| PostgreSQL | 业务表带 `tenant_id`，DAO 查询强制过滤；跨租户仅在超管接口按显式 `tenant_id` 参数 |
| Milvus | 集合 `agent_rag_docs` 以 `tenant_id` 为分区键，检索 `expr: tenant_id == "..."` |
| Redis | key 前缀 `t:{tenant_id}:u:{user_id}:...`（短期记忆、停止标记） |
| MinIO | 对象键按租户前缀组织 |

## 7. 异步任务零信任

MQ 消费端不信任生产端，处理前重新鉴权：

```python
await authorize_task(msg.header.user_id, msg.header.tenant_id, [Scope.UNIFIED_TURN_REVIEW])
```
用于 `qa.ragas_review`（RAGAS 测评）与 `qa.parse`（`unified_file:upload`）等任务。

## 9. 排障清单

| 现象 | 排查 |
|---|---|
| 401 | token 过期 / Redis 会话被清（`jti` 不存在）/ 未带 `Authorization` |
| 403（接口） | 角色缺对应 `资源:动作`；超管调租户接口 |
| 菜单不显示 | `agent_menu.scope` 未授权 或 `visible=false` |
| 检索恒空 | 不是权限问题，看 `rag.retrieve.empty tenant=?`（租户上下文丢失） |
